# Gemini CLI S8：事件、遥测与审计边界

## 范围与证据等级

本片基于 S8 目录中已落盘的 Gemini CLI 官方公开源码、测试和固定来源资料整理；未执行真实 Gemini CLI 任务，未访问真实服务、凭据或任何受保护目标。

- `verified`：官方源码/测试直接显示。
- `inferred`：由源码结构合理推导，但不是显式承诺。
- `unknown`：已审查资料未证明，不能补全。

## 结论

### C1 — verified：事件模型包含工具调用状态和关联字段

官方 `ToolCallEvent`、事件 translator、turn 类型和相关测试显示，工具调用事件能够携带调用标识、工具名称、参数/结果摘要以及状态转换信息；事件可被 MessageBus 转发给 UI、logger 或其他订阅者。测试证明的是事件转换和状态行为，不是外部业务效果。

来源：见 `sources.md` 1–5。边界：字段存在不等于所有字段始终存在，也不等于事件不可篡改或永久保存。

### C2 — verified：状态事件可表达成功、错误、取消等过程终态

源码和测试覆盖工具调用的成功、错误、取消/中断路径，并由 translator/logger 进行展示或导出。该证据证明客户端过程状态可被表达和传播；不证明下游服务已提交、回滚或未执行。

来源：见 `sources.md` 2–6。边界：`success` 是客户端工具路径结果，不是业务 postcondition。

### C3 — verified：telemetry 使用 OpenTelemetry 语义和属性进行运行关联

已核验的 telemetry 类型、属性、semantic 与 SDK 代码支持 trace/span/log 等运行关联，以及工具/模型相关属性。其用途是观测、诊断和关联，不是业务事务账本。

来源：见 `sources.md` 7–10。边界：不能从属性字段推导完整审计、业务提交或因果关系。

### C4 — inferred：MessageBus 与 logger/exporter 构成可用的过程证据链

事件总线、状态快照、终态回调与日志/文件导出可以拼接出一次客户端运行的过程证据链。这是基于组件连接方式的受限推断，不等于不可变、完整、持久化或跨实例一致的审计链。

来源：见 `sources.md` 3–6。边界：必须额外验证落盘成功、送达、保留策略、完整性保护和时钟/身份绑定。

### C5 — unknown：事件/telemetry 的完整性、送达、持久性和无损性

本片官方资料没有建立以下保证：所有事件必然发出、订阅者必然收到、文件/telemetry exporter 必然成功、进程崩溃前事件必然落盘、长期开启的遥测必然保留、事件流不可篡改或不可丢失。因此这些属性保持 `unknown`。

### C6 — unknown：事件状态不能证明外部业务效果或 exactly-once

本片没有证明：客户端工具成功等于远端提交、取消等于远端未执行、错误等于远端未产生副作用、重试不会重复副作用、事件 ID 是远端幂等键，或系统具备 exactly-once。业务效果需要目标侧权威 read-back、postcondition、幂等协议、对账或补偿证据。

## 证据边界

本片只证明 Gemini CLI 客户端内部事件/遥测的结构和过程语义。它不证明生产可用性、审计合规、业务成功率、远端提交、回滚、幂等、exactly-once 或用户效果。所有未覆盖项保持 `unknown`，而非否定其可能存在。
