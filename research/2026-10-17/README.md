# Northstar：编程优先的生态研究与攻防增量

**本轮决策：先编程，后多模态；攻击工具和防护工具同步建设。** 研究范围不是把所有 AI 功能并入一个运行时，而是为 Northstar 的真实仓库任务闭环找到可验证增量。

已完成十条公开研究轨道：[Codex](01-openai-codex.md)、[Claude](02-anthropic-claude.md)、[Gemini/Jules](03-google-gemini.md)、[开源编程 Agent](04-open-source-coding.md)、[编排框架](05-orchestration.md)、[互操作与身份](06-protocol-identity.md)、[隔离执行](07-sandbox-execution.md)、[持久执行与记忆](08-durable-memory.md)、[可观测性与评测](09-observability-evals.md)和[公开社区信号](10-community-radar.md)。每份报告引用已打开核验的一手文档或仓库。

[综合研究与候选裁决](00-ecosystem-synthesis.md)将最优先的缺口集中于冻结模型/环境的基线、持久审批恢复、仓库准入、跨产物证据关联，以及阶段恢复。现有 worktree、SubmitPlan、独立检查和 delivery seal 不重复实现。

## 本轮研发切片

第一项增量是**编程运行证据硬门**：检查本地证据的完整性、阶段与效果顺序、检查回执和交付补丁关联。它不能把模型的“已完成”当作成功，也不能把有效的失败证据当作通过验证的成功。

第二项增量是**本地编程攻防实验室**：用确定性攻击与良性对照分别测试计划闸门、治理配置保护、路径边界、检查伪造、检查污染交付内容，以及硬预算。攻击提议、门禁拒绝、处理器进入、实际有害效果和正常效用分别记录，不把“全拒绝”算作有用防护。

两个增量仅在脚本/实验入口中，未加入默认生产工具集。测试使用本次拥有的临时仓库，不接受外部靶标，不使用真实凭据，不声称覆盖真实模型的全部攻击。

## 待继续推进

下一里程碑仍是固定真实模型、版本和隔离环境后的完整 24 题基线。小样本真实模型试验只用于发现问题，不能当作发布成功率；参考补丁通过率也不能冒充模型能力。

之后补齐持久审批与阶段恢复。扩大攻防时优先加入恶意仓库上下文、依赖输出注入、MCP 定义漂移和子 Agent 委派的配对场景；工具接入必须遵守现行 [Core/Labs 蓝图](../../docs/next-gen-agent-blueprint.zh-CN.md)。多模态只有在编程门槛连续两个里程碑保持后再进入产品主线。
