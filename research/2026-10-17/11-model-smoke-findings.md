# 三题双次真实模型编程试验：公开检查不等于隐藏验收

## 结论

本轮确实通过 Northstar 的编程产品路径调用了真实 `gpt-5` 模型，而不是用参考补丁冒充模型输出。三道 Python 任务各运行两次，共六次尝试。**五次运行的宿主声明检查通过，但六次交付补丁都未通过独立隐藏验收。** 每次原始 fixture checkout 均保持不变，起点 commit 与独立补丁评测起点一致。

这说明现有运行时的 `success` 表示宿主实际声明的检查通过，不代表任务包的隐藏验收、完整产品要求或发布资格通过。新的证据硬门必须保持这一语义边界，不能把一致的证据链再包装成不存在的基准成功。

## 固定条件与限制

试验使用 `gpt-5` 的 provider alias，`reasoning.effort=minimal`，每次最多 16 turns、40 tool calls、4096 output tokens 和 0.5 USD 的运行时成本上限。运行前记录代码、任务包与环境摘要；合同文件 SHA-256 为 `6d78e8337ab5671f729758d8bc42b1473f9761739c1981bf7adb8dbe189f860c`。

模型执行使用 Bubblewrap 只写工作区的隔离和独立网络 namespace；不启用 Fetch 或 MCP。provider 请求在宿主侧发送。宿主的 Bubblewrap seccomp 实测探针报内核 EINVAL，因此这次开发试验显式关闭该过滤层，未修改 Northstar 的安全默认值。独立任务包评测器仍报告 `network_enforced=false`。试验结束后恢复原先离线测试的工具环境。

模型不可变 revision 不可得，样本极小，且评测环境未满足完整发布硬门，所有结果均标记 `release_eligible=false`。**这不是一个冻结完备的正式模型基线，不能推出模型的总体成功率或安全率。** 测试过程中未向模型暴露隐藏验收文件，未在看到隐藏失败后重写提示并将重试并入同一基线。

## 三类具体偏差

- **有界重试修复，两次尝试：** 公开测试通过；隐藏验收揭示非正 `max_attempts` 的合同处理仍有缺口。运行时的补丁 replay 和宿主检查并没有凭空补上该边界行为。
- **批量名称归一化，两次尝试：** 公开测试通过；独立验收揭示零 limit 与空输入的边界行为不符。模型自发添加的参数限制可能过度约束 API，必须从公开需求或源码合同验证，而不能因为新增检查看起来严格就认可。
- **时钟相关测试修复，两次尝试：** 一次公开检查通过但独立验收失败；另一次没有形成有效交付并以 `error_postconditions_failed` 终止。前者验收还约束至少三个独立测试方法，公开提示只要求修复 flaky timeout 且不弱化断言，因此正式基线前需要复核这类结构性验收约束的公开合同依据，不能不加审查地将所有失败归咎于模型。

## 下一步工程要求

下一轮先冻结完整 24 题的模型、不可变 revision（不可得则明确缺失）、环境和预算，再记录每题多次尝试。公开需求需让 API 边界可发现；隐藏测试应检验需求，而不引入未经公开的任意实现形状。

编码完成前的验证阶段应检查输入边界、旧合同回归和测试覆盖，而不只运行原本就少量通过的公开测试。仍由宿主拥有检查命令和成功判定，模型不得修改隐藏 evaluator、治理策略或交付封印。

本轮没有通过修改基准、降低隐藏验收门槛、复制参考补丁、提高所有预算或宣称“安全平均分”来消除失败。原始六次事件流、补丁、阶段日志、宿主检查和独立评测回执保留在随交付提供的验证包中。
